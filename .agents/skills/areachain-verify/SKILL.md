# AreaChain 变更验收

将当前改动与项目已有验证入口对应起来。本技能只负责选择、执行和解释检查，不把验证请求当成修复、安装或外部写入授权。

## 项目与输入

- 从本技能目录向上三级定位 [仓库根](../../..)，确认 `AreaChain.xcodeproj`、`AreaChainTests` 与 `scripts/build.sh`；所有仓库命令在这个根目录执行，不使用技能目录作工作目录。
- 遵循 [项目 AGENTS.md](../../../AGENTS.md)，实际环境要求见 [README.md](../../../README.md)。目标不是本仓库或其工作副本时，不套用这里的命令与测试名。
- 读取 [技能路由](../../../skill-routing.md)；涉及公共控件、主题或复用边界时读取 [共享组件与复用目录](../../../docs/component-catalog.md)，核对变更是否更新了真实消费者和相应证据。
- 读取 [质量门禁](../../../docs/quality-gates.md)；统一质量入口是 `python3 -B scripts/quality_gate.py`，本技能负责按影响补充它不能替代的 Swift、构建和原生证据。
- 获取本次变更范围、用户预期、相关宿主/数据契约，以及已有验证记录；保留用户的其他修改。来源不足时先做安全检查，不能猜测测试已经覆盖。
- 执行前完整阅读 [验证入口与边界](references/checks.md)，只运行本次适用部分。若用户只要验证计划，输出计划而不启动测试或应用。

## 选择检查

| 改动 | 起点 |
|---|---|
| 文档、AGENTS.md、技能元数据 | 工作流静态检查、差异与作用域、技能结构及必要的发现检查；不因此构建应用 |
| Domain 依赖边界或本地检查器 | 工作流静态守卫及其反例测试；Swift 行为变化仍需对应 Swift 测试 |
| 领域规则、解析、日期、筛选 | 对应 Domain 测试；按真实消费者补 Services/Features 覆盖 |
| 仓储、保存、快照、附件或同步逻辑 | 对应 Services 测试与兼容/失败路径；只使用隔离数据 |
| 样式、输入、窗口或其他 UI | Theme/Features 测试，加相关原生宿主的语言、主题、尺寸和交互证据 |
| 构建、签名检查或应用管理脚本 | `scripts/tests` 与脚本语法检查；不替代真实安装或系统认证 |
| 发布候选包核对 | 仅在当前请求需要时构建/验签；不把 Release 等同测试通过或正式发行 |

这些是选择起点，不是每次全部运行。先确认候选测试存在且覆盖目标；共享行为变化扩大到相关调用方，而不是只跑最容易通过的一组。

## 执行和解释

1. 核对工具、工作目录与隔离条件；环境检查失败时区分依赖问题和代码失败，不自动安装软件、改签名或扩大权限。
2. 运行选定检查，记录实际命令、配置、结果和必要产物；区分通过、失败、跳过和未运行。测试命令退出成功但目标用例被跳过，不算该行为通过。
3. UI 的功能操作与视觉检查分别核对，原生焦点敏感测试串行执行，不同时操作其他窗口或靠跳过断言消除失败。
4. 失败先收集证据并缩小原因。独立验证请求只报告问题；处于已授权开发任务时，由负责实现的主代理修复范围内问题，再重跑相关检查。
5. 公共契约、持久化语义、复杂状态、跨模块行为或高风险变更，按适用规则提供独立只读复核材料；复核不是测试或用户授权的替代。

## 输出与边界

- 输出变更/声明与证据的对应关系、实际通过项、失败/跳过/未运行项和残余风险；计划中的检查不能写成执行结果。
- 明确编译、单元测试、隔离集成、真实原生交互、系统认证、安装和发行是不同验收层级。
- [工程手册](../../../docs/engineering.md) 保存生命周期覆盖和待补证据；本地检查脚本通过不证明远端 CI、合并门禁或完整恢复流程已生效，不把历史测试结果当成本次结果。
- 后续相关编辑使证据失效时重跑受影响项。必要验证未完成则报告部分完成，不仅靠解释阻塞就宣称交付。
- 不读取真实手记、附件或凭据做测试材料；不启用真实钥匙串测试、不写真实日历、不修改个人签名、不自动安装/卸载/启动日用应用。
- 真实认证、数据迁移、签名身份变更及发布验收需要另行界定和确认，不是本技能默认继续的步骤。
